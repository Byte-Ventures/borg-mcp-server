# Repository Guidance

## Setup And Checks

- Use Node.js 22.12+ and npm 10+. Install exactly with `npm ci --ignore-scripts --registry=https://registry.npmjs.org`; lifecycle scripts are intentionally disabled.
- Run one test file with `npm test -- test/<name>.test.ts`. The `pretest` hook builds first because some tests inspect the ignored `dist/` output.
- Before handing off a change, run `npm run check` (build, strict typecheck, full Vitest suite). CI separately runs `npm audit --audit-level=high`.
- There is no lint or formatter command. Do not invent one or reformat unrelated code.
- `dist/` is generated by `npm run build` and ignored. Never commit it.

## Code Map

- `src/main.ts` is the executable entry point: `runMain` calls `runCli` in `src/cli.ts` with `nodeServerService` from `src/service.ts`.
- `src/service.ts` composes bootstrap, credentials, SQLite, HTTPS, runtime updates, and the dashboard. Keep transport parsing in `src/https-server.ts` and protocol behavior in `src/coordination-api.ts`.
- `src/store.ts` owns SQLite persistence and authorization. Request code must use a server-derived `Principal` and `StoreRuntime.forPrincipal()`; never expose or pass a raw database handle around this boundary.
- `src/index.ts` is the public library surface. Export changes affect the packed API even when the CLI is unchanged.
- Portable protocol decoders, paths, templates, and conformance live in the separately released `borgmcp-shared` dependency. Change that contract there first, then consume an exact published version here.

## Invariants

- Preserve loopback-only defaults. Private-LAN binding requires both an explicit non-loopback host and `--lan`; HTTPS is TLS 1.3.
- Keep `borg-mcp-server start` foreground-only; it must not install or load a managed service.
- Keep runtime bootstrap offline. `test/no-egress.test.ts` permits outbound fetch only in `src/registry-artifact.ts` and subprocess creation only in runtime/service lifecycle code.
- Authorization changes require accepted-path and rejected-path tests, including cross-cube isolation where scope can change. `test/conformance.test.ts` runs the shared adapter contract.
- Migrations are the ordered `STORE_MIGRATIONS` array in `src/migrations.ts`. Never edit a migration that appeared in a published version; append a new version and append its evaluated checksum to `src/migration-checksums.ts`. Run `npm test -- test/migrations.test.ts` for migration work.
- Keep operator-facing errors secret-free and mapped through `src/operator-error.ts`; debug output must use the centrally redacted logger.

## Release Boundaries

- Dependencies and devDependencies are exact registry versions in `package.json` and `npm-shrinkwrap.json`; do not add Git/SSH dependencies, registry redirects, install hooks, or bundled dependencies.
- Release identity is generated and allowlisted by `scripts/release-identity.mjs`. Do not manually bump version literals or edit `docs/release-records.json`.
- Packing checks are stricter than ordinary tests. When explicitly preparing an artifact, run `node scripts/verify-source-lock.mjs`, then verify and exercise the exact tarball with `scripts/verify-packed-artifact.mjs` and `scripts/exercise-packed-artifact.mjs`.
- A commit or merged release-prep PR does not authorize tagging or publication. Follow `docs/releasing.md`; never create, move, reuse, or rerun a release tag without explicit authorization.
