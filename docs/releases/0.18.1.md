New Software Development cubes now use the coordination and release policies published in `borgmcp-shared` 0.12.3.

- Coordinator instructions require one proof per property, one Code Review for mechanical changes, and delta review for successor revisions.
- Builder instructions favor focused verification without duplicate green-CI runs, while release instructions use automatic tag staging with npm stage approval as the sole human publication boundary.
- Server creation and read-back coverage verifies that the seven-role template, role descriptions, human/default assignments, presentation, and message routing remain unchanged.
