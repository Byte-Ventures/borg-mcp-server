Managed service uninstallation now provides a safe, explicit removal path while preserving local server state.

- `borg-mcp-server service uninstall [--json]` stops and removes an active launchd agent or systemd user service, removes an inactive definition, and reports an already-absent service idempotently.
- Uninstall removes only owner-private, single-link definitions recognized through the same Borg ownership and published legacy-shape checks as installation, with content and inode revalidation immediately before deletion.
- Server data, identity, credentials, verified runtime artifacts, and managed logs remain untouched across successful removal, refusal, and recovery paths.
- Controller or filesystem failures return bounded definition, service, recovery-command, and stable-runtime-identity diagnostics without exposing raw platform errors.
- Missing definitions with observed leftover registrations fail without mutation and provide platform cleanup guidance; failed controller probes remain distinct, and status does not suggest an unusable restart.
