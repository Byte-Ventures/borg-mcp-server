# borgmcp-server 3.2.0

- Reports a database failure in the liveness watchdog as a typed, redacted `LIVENESS_SCAN_FAILED` line on server stderr instead of silently discarding it. The watchdog keeps ticking, reports once per consecutive failure episode, and re-arms reporting after a successful scan.
- Corrects a previously false operator-reference statement about wake retries: the two-ping bound counts delivered pings, not elapsed time, so an offline recipient consumes no attempt and an arbitrary interval may separate deliveries. The corrected reference also documents delivery to the entry's recipient list, co-recipient wake events, and the ephemeral, non-durable, non-replayed behavior.
- Replaces the generic invalid-query response with distinct messages for disallowed, unknown, repeated, empty, and malformed coordination query parameters while preserving HTTP 400 and the `INVALID_INPUT` code.
