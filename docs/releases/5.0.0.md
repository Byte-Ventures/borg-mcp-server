# borgmcp-server 5.0.0

**Breaking:** Uses `borgmcp-shared` 3.0.0 and exact protocol tag **15**. Upgrade
with a matching protocol-15 client; protocol-14 consumers fail closed. There is
no protocol fallback or credential recovery mechanism.

Adds enrolled-parent inspection, finalization and explicit retirement of exact
pending attachment operations. Parent-scoped cancellation fences prevent a
delayed attach from creating a drone after cancellation. Finalization protects
completed attachments from pending-only retirement, and general eviction still
requires cube management access. Receipt locators never authenticate a request
or restore a bearer.

Ordinary retries with the original bearer preserve the same drone, session and
initial log cursor, including the existing optional-current-prior behavior.
Migration 30 preserves established state. A pre-existing session without an
operation record is conservatively protected as finalized on reuse, not made
eligible for pending-only retirement. Revoked, evicted, superseded and foreign
sessions remain refused.

This is the server half of the coordinated
[failed-attachment recovery work](https://github.com/Byte-Ventures/borg-mcp-client/issues/169).
At this server-first release, the matching client release and its published
printed-command/crash recovery journey remain pending. Server transaction,
previous-published-state upgrade and package evidence do not establish that full
client journey or recovery of erased credentials.
